# iSince

「散髪したのは前回いつだったか」のような、日常の行動・作業について
**前回いつ実施したか**と**前回から何日経過したか**を素早く確認するための記録ツールです。

タスク管理やリマインダーではなく、過去の実施記録と経過日数の把握に特化しています。

## 主な機能

- 記録対象（項目）の追加・名称編集・削除
- 実施記録（実施日・簡易メモ）の追加・編集・削除
- 一覧画面でのカード表示
  - 前回からの経過日数を大きく表示
  - 前回実施日・過去の平均的な実施間隔・直近メモを表示
  - カードから直接「今回を記録」できる（詳細画面を開く必要なし）
  - 経過日数がいつもの間隔より長い場合、控えめな参考情報として表示（色だけでなく文字でも表現）
- 詳細画面
  - 前回実施日・経過日数・平均間隔・中央値・最短間隔・最長間隔を表示
  - 履歴を新しい順のタイムライン形式で表示し、記録と記録の間の日数を表示
- 並び替え（経過日数が長い順 / 最近記録した順 / 名前順、初期表示は経過日数が長い順）
- データはブラウザの `localStorage` に自動保存され、再読み込み後も保持されます
- 全データのJSONファイルへの書き出し（バックアップ）と読み込み（復元）

## 使い方

`iSince.html` をブラウザで開くだけで利用できます。サーバーやビルド、外部APIは一切不要です。

1. 「＋ 項目を追加」から記録したい項目（例: 散髪、洗車、歯科検診）を追加
2. 項目カードの「＋ 今回を記録」から実施日とメモを記録
3. カードをクリックすると詳細画面（統計・履歴タイムライン）を確認できます
4. 詳細画面から過去記録の編集・削除、項目名の編集・削除が可能です
5. 一覧画面の「バックアップ」「復元」から、データの書き出し・読み込みができます（詳細は後述）

`main` ブランチへの `iSince.html` の変更は GitHub Actions（`.github/workflows/pages.yml`）により
自動的に GitHub Pages へデプロイされます。

## データの保存について

- すべてのデータはブラウザ内の `localStorage`（キー: `isince.data.v1`）に保存されます。
- サーバーへの送信や外部APIとの通信は行いません。
- 保存データは将来の仕様変更に備えて `version` フィールドを持っています。

### データ構造（概要）

```json
{
  "version": 1,
  "items": [
    {
      "id": "任意の一意なID",
      "name": "散髪",
      "records": [
        { "id": "任意の一意なID", "date": "2026-08-15", "memo": "夏なので少し短め" }
      ]
    }
  ]
}
```

平均・中央値・最短・最長などの統計値は保存せず、`localStorage` からもバックアップからも、
常に `records` の日付から都度計算します。日付は入力順ではなく日付順に並べ替えて間隔を計算するため、
記録を過去に遡って追加しても、同じ日に複数回記録しても、統計は正しく求められます。

## バックアップ・復元

`localStorage` はブラウザやデバイスに紐づいた保存先のため、ブラウザのデータ消去や機種変更で
記録を失うおそれがあります。それとは別に、利用者が任意のタイミングで全データをJSONファイルとして
退避・復元できるようにしています。

### バックアップ

一覧画面上部の「バックアップ」ボタンから、現在の全項目・全記録をJSONファイルとして
ダウンロードできます。ファイル名には出力日が入ります（例: `iSince-backup-20260816.json`）。

バックアップJSONは、単なる `localStorage` の中身ではなく、iSince のバックアップファイルであると
判別できる形式で出力されます。

```json
{
  "app": "iSince",
  "backupVersion": 1,
  "exportedAt": "2026-08-16T10:56:00+09:00",
  "data": {
    "version": 1,
    "items": []
  }
}
```

### 復元

一覧画面上部の「復元」ボタンからJSONファイルを選択します。

- 選択したファイルは、`localStorage` へ書き込む前にまず内容を検証します。
  iSince のバックアップとして認識できない場合、対応していない `backupVersion` ・`data.version` の場合、
  必須項目（項目ID・項目名・記録の配列・記録ID・日付など）が欠けているか形式が不正な場合は、
  **現在のデータを一切変更せず**、エラーであることが分かるメッセージを表示します。
- 検証に通った場合も即座には上書きせず、現在の項目数・記録件数と、それが置き換えられることを
  明示した確認画面を経てから復元を実行します。
- 復元後は再読み込みをしなくても画面に反映され、再読み込み後も保持されます。

## ご利用上の注意

- **ブラウザのデータ（サイトデータ／閲覧履歴）を消去すると記録も消えます。** 大切な記録は
  「バックアップ」で手元にJSONファイルとして残してください。
- **復元は、現在のデータをバックアップの内容で完全に置き換えます。** 現在のデータとバックアップを
  マージする機能はなく、置き換えは元に戻せません。今のデータを残したい場合は、復元前に
  「バックアップ」を実行してください。
- ローカルのファイル（`file://`）で開いた場合と GitHub Pages で開いた場合とでは、`localStorage` の
  保存先が別になり、記録は共有されません。一方から他方へ移すには「バックアップ」と「復元」を使ってください。
